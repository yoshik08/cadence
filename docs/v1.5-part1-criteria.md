nothing touches the real account. Measured 2026-11-12.

## Build

## Design language and motion
- [x] `ui/tokens.slint` exists; `python scripts/lint_tokens.py` reports 0 hex colours and 0 loose px / ms literals outside it. Map: `docs/v1.5-part1-audit.md`.
- [x] Shared `Button`, `IconButton`, `Card`, `SectionHeader`, `ListRow` in `ui/base.slint` with default, hover, pressed, focused and disabled states; all screens use them.
- [x] All animations use the token durations (120 / 200 / 320 ms) and easings.
- [x] Nothing animates while idle: 0 ms CPU over 30 s idle; 78 ms over a 5-minute run (0.026 % of one core). Mini-player and podcast timers run only while needed.

## Loading
- [x] Launch shows cached Home, Liked Songs, playlists and sidebar before sign-in: window at +200 to 280 ms, Home from cache at +320 to 405 ms (59 cards).
- [~] Background refresh updates in place (models patched, not reset; unit-tested). The live refresh needs a signed-in run.
- [x] Cache holds no tokens or client ID: 807 real cache files checked, 0 matches. Writes are atomic with unique temp names.
- [x] 1000 liked songs and 1000 playlists scroll with no spinner and no blocking: per-step gap 17 to 36 ms over repeated full sweeps (one 68 ms outlier).
- [~] One shared HTTP client, in-flight GETs deduped, 429 waits Retry-After, capped backoff (unit-tested). Live 429 behaviour not exercised.

## Art
- [x] Visible rows first (newest first), prefetch two screens ahead, queued work dropped on navigation, art for rows far off screen released.
- [x] Cached art appears at once (memory hits are set synchronously); downloaded art fades in over the `#282828` placeholder.
- [x] No decoding or HTTP on the UI thread (debug assertion in both paths).
- [x] `pick_image` used for every art slot. Exceptions by design: the media flyout uses librespot's largest cover (640 px); local-file art comes from the file.
- [x] Mini player cover matches its slot: 72, 90 and 108 px at 100, 125 and 150 % (snapshots).
- [x] Covers use `image-fit: cover` with smooth scaling. Exceptions by design: the karaoke word textures and stage background (`fill`, exact size) and the logo (`contain`).
- [x] Decoder chosen by measurement (`scripts/bench-decode`): zune-jpeg + fast_image_resize is 1.7x to 2.9x faster except for big downscales, where the current decoder stays.

## Memory and renderer
- [x] Caches bounded (art 12 MB / 256 images, bodies 4, API in-flight map, titles, nav history); player events on a bounded channel.
- [x] Memory plateaus. 3-minute test (Liked Songs 3x, then 10 playlist opens): 18.1 MB before, 28.5 MB after the sweeps, 41.3 MB at the end; private bytes flat at 133 to 141 MB. 20 playlist opens: settles at 36 MB.
- [~] femtovg kept. The comparison was cut short and is deferred. Partial numbers from a 1000-playlist sweep: Skia used 7 MB less working set but twice the private bytes (289 MB against 145 MB), drew cached Home 500 ms later, and makes the exe 8.2 MB larger (29.7 MB against 21.5 MB).

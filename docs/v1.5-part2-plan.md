Status: **waiting for approval**. No code has been changed. Branch `v1.5-part2`, created from
`v1.5-part1` (`ec95a76`). Written 2026-11-12.

## 1. Decisions I need from you

Each has a default; "approved" means the defaults.

| # | Question | Default |
|---|---|---|
| P1 | **Equalizer and CPU.** The GPU renderer redraws the whole window on every animation frame, so a smoothly animated equalizer keeps Cadence drawing at the display rate (up to 165+ fps) for as long as the playing row is on screen. | Stepped bars: new heights 8 times a second with no tween between steps. It reads as a live equalizer and costs about 8 frames a second, only while playing and only while the row is visible. I will measure CPU while playing and report it. |
| P2 | **Enter plays the "focused row"**, but rows have no keyboard focus today. | Single click selects a row and gives the list keyboard focus; Up / Down move the selection; Enter plays it. Space stays the global play / pause key (the list passes it through). Up / Down are the only new keys. |
| P3 | **Tooltips.** Slint 1.18 has no public tooltip element. | One shared tooltip in the main window, shown after 500 ms of hovering a play / pause button, near the pointer. One instance for the whole app; its delay timer runs only while something is hovered. |
| P4 | **The queue** has drag-to-reorder and a remove button that other lists don't. | The queue uses the list variant of TrackRow, with the drag handle and remove button kept as queue-only slots. Its rows grow from 52 to 56 px to fit the 48 px cover. |
| P5 | **Artist Popular tracks**: the spec names table variant for Liked Songs, playlists and albums, and lists Popular separately. | Popular uses the list variant (cover, title, artist; heart, duration, more), like Spotify's artist page. |
| P6 | **"More" button** on rows. | Opens the existing context menu for that track, at the button. |
| P7 | **Album link in the player bar.** librespot's track event carries the artists with their IDs but only the album's name. | Artist links work at once. The album ID comes from the metadata lookup the queue panel already makes (one request per track change); the title becomes clickable when it arrives, usually within a fraction of a second. |
| P8 | **Mini player links.** | Same targets as the bar. Clicking a link brings the main window forward and opens the page there; the mini player stays open. |

## 2. What exists today

- **Rows**: `TrackItem` (`ui/widgets.slint`) is the only track row: # | Title + artist below | Album | Date added | Time, plus an "Artist" header column that has no cells under it (the empty Artist column you saw). No cover, no play button; double-click plays. The queue has its own `Row` (`ui/queue.slint`); artist Popular uses `TrackItem`.
- **Playback from a list**: `Browse.play(context, i)` → `browse::play_row`. It plays the context URI from row i when the list is in its natural order, else the rows as shown (`play_list`), and handles Popular, podcasts and local files. A row's play button will call this same function.
- **Track art data**: `TrackData.image` is one URL: from the library index for Liked Songs (64 px), and Spotify's first (largest, 640 px) image for playlists and albums. No image list, so `pick_image` can't choose yet.
- **Track models**: `tracks` and `popular` are `VecModel<TrackRow>`, patched in place since Part 1. Card lists use Part 1's `LazyCards`, which requests art as rows are shown.
- **Player bar**: one click area over cover + text opens lyrics; the heart is an absolutely placed button at the far end of the left section. `Playback` holds only title, artist and album names.
- **Back / forward**: since Part 1 they are the shared `IconButton`, whose circle and chevron share one centre. The offset you saw was v1.4's `RoundIcon`, whose glyph sat at a fixed 11 px for a 44 px button shrunk to 32. I will confirm with a snapshot of the hover state.
- **The sync label**: two labels (`ui/side.slint`, `ui/lyrics.slint`). Both show the offset ("+0.3s") when it isn't zero.
- **Sidebar filter**: a `Field` bound to `Browse.side-filter`; `browse::fill_sidebar` filters by name and already keeps Liked Songs (but filters it out when the text doesn't match "Liked Songs").

## 3. Steps and commits

`cargo build` and `cargo clippy` after each step; criteria re-read after each.

**A. TrackRow (commit A)**
1. Data: `TrackData` gets the image list (`Vec<SpImage>`) instead of one URL; Liked Songs builds a two-entry list from the index (64 / 300 px). The `TrackRow` struct gets `art`, `fresh`, `artist-uri`, `album-uri`.
2. One art-loading model: Part 1's `LazyCards` becomes a generic `LazyArt<T>` (cards and track rows both carry `art` + `fresh`). Library rows, card grids, the track table, Popular and the queue all use it. Still one queue, one cache, one loader; visible rows first, prefetch ahead, art released far from the viewport. `patch_model`, hearts and sorting work on it as they do on `VecModel` now.
3. UI: `TrackRow` in a new `ui/track_row.slint` on top of `ListRow`, with `variant: "list" | "table"`. The table drops the Artist column and splits its width between Title and Album; header and cells share one column definition (as now via `TrackColumns`), so they line up. Cover: Part 1 `Cover` (placeholder + music note only before first load, fade-in, 4 px radius, cover fit).
4. States: idle / hover (50 % black overlay + white triangle on the cover, or the triangle in the # cell; heart and more appear, heart stays if liked) / current (accent title; equalizer while playing, pause on hover; static accent number or triangle while paused) / unavailable (dimmed, play disabled). Only opacity and colour change on hover, so nothing reflows.
5. Actions: the play button calls `Browse.row-play(i)`: pause if this row is current and playing, resume if current and paused, else `play_row` with the list's context (no new playback path). Double-click plays; single click selects; Enter and Space as in P2. Tooltip per P3.
6. Replace `TrackItem` in Liked Songs, playlists, albums, artist Popular, the Find section and the queue. Export `TrackRow` so Part 3 can use it for search.
7. Check: 1000-song sweep from Part 1 (scroll gaps, memory against Part 1's numbers), and CPU while playing with the playing row visible.

**B. Player bar targets (commit B)**
1. `Event::Track` carries the artists as (name, uri) from `artists_with_role`; the album URI comes from `queue::player_meta` (P7). `Playback` gets `album-uri` and `artists: [ArtistLink]`.
2. Bar: cover toggles lyrics (pointer cursor); title opens the album (underline on hover); each artist is its own link, commas plain text; links underline on hover. A long list fits by eliding the artist that crosses the edge and hiding the rest, so each visible name stays clickable. Local files and episodes: plain text. Right-click on the track keeps opening its menu. No link touches playback.
3. Mini player: same, per P8.

**C-E. Heart, back / forward, sync label (commit C-E)**
- C: cover, title / artist column (content width, elided) and heart in one start-aligned `HorizontalLayout`, 12 px gap, centred on the text block.
- D: verify the round `IconButton` (fixed size, centred icon, full radius) with a forced-hover snapshot; fix only if it is off.
- E: remove both zero-offset labels; keep the −0.1 s / +0.1 s buttons. The offset readout ("+0.3s") stays in the same spot when the offset isn't zero, as the spec says; at zero, the spot is empty. A repo-wide search for the old wording must come back empty (docs included).

**F. Sidebar Playlists search (commit F)**
- The Filter field is replaced by a "Playlists" subheading (caption size, muted, list-item alignment), with folder and + right-aligned on the same row.
- `Browse.side-search-open: bool`. Clicking the subheading swaps in a search field of the same height with a magnifier and "Search playlists", focused. Typing filters live through the existing `side-filter` and `fill_sidebar`. Escape with text clears and collapses; Escape or click-outside when empty collapses; collapsing clears the filter.
- `fill_sidebar` always keeps Liked Songs, whatever the filter.

**Wrap-up**: token lint and a manual Design Review pass over the new components, unit tests, update the criteria file, commit.

## 5. Risks

1. **Generic art model**: moving tracks from `VecModel` to `LazyArt` touches sorting, hearts and the cached-then-refreshed list path from Part 1. Covered by the existing unit tests plus a new one, and by the sweep.
2. **Equalizer cost** (P1): measured, not assumed.
3. **Artist link eliding**: Slint layouts don't elide across several items, so the fitting is computed per name. Very long single names elide on their own.
4. **Rows are 4 px taller** in the queue (P4), and table rows gain a 40 px cover in the Title cell. Row height stays 56 px everywhere (from 52), so lists get slightly longer.
5. Out of scope and untouched: search page and Top result, Home Recently played, autoplay, client ID, updater, login and tokens, version.

## 2. What exists today (short)

- **Startup**: `browse::init` runs only after `Web::connect` (token read, possibly a refresh round trip). Nothing from disk is shown before that. This is the main launch delay.
- **Cache**: `cache.rs` writes atomically (temp + rename) and prunes by size. `api::get` is cache-then-network, not stale-while-revalidate: a stale entry blocks on the network, a fresh one is never revalidated. The library (liked, playlists, albums, artists, shows) is mirrored in SQLite.
- **HTTP**: two `reqwest` clients (`web.rs`, `art.rs`). No in-flight dedupe for API calls. 429 waits `Retry-After` only when it is 30 s or less, 3 tries; no backoff for 5xx or network errors.
- **Lists**: Liked Songs, playlist tracks, the library page and the sidebar are already `ListView`. Search results, "Show all" grids, artist discography and Home are `ScrollView` + `for` (not virtualized). Playlist pages load 50 at a time and rebuild the whole model on every page, which is O(n²) and resets the list.
- **Art**: decode is already off the UI thread (`spawn_blocking`, `jpeg-decoder` with DCT downscale, box filter). Memory LRU keyed `url@px`, 24 entries / 6 MB. Disk cache 192 MB. 4 parallel loads. Missing: priority, cancellation, prefetch, fade-in, small-then-sharp swap. Disk-cached art queues behind downloads on the same semaphore.
- **Blurry mini player, root cause**: the mini player reuses the bar image, decoded at 56 px, and shows it at 72 px. Second cause found: the SQLite library stores one 64 px URL per item (`library::pick_small`), and Home shelves show those at 160 px.
- **Idle timers**: mini player 500 ms timer runs forever once created; podcast 15 s timer always runs; two `Timer`s in `lyrics.slint` are already gated by `running:`.
- **Icon plumbing**: `cadence.rc` (exe + tray via `LoadIconW`), `taskbar.rs` (`include_bytes!` to `%LOCALAPPDATA%\cadence\cadence.ico` for the app ID and media flyout), `app.slint` and `mini.slint` window icons, README (no header image today).

## 3. Steps, in order

Each step ends with `cargo build`, `cargo clippy` (no new warnings against a baseline taken in step 0), and a re-read of the criteria file. Work happens on branch `v1.5-part1`; one commit at the end unless you prefer one per step.

**0. Baseline.** Branch. Record clippy warnings, exe size, and working set / CPU at idle. Take reference snapshots of every page with the existing `CADENCE_DEMO` / `CADENCE_ROUTES` / `CADENCE_SHOTS` harness, to diff against after the token migration.

**1. Icon (H).** `git add` then `git mv icons8-spotify-1024.png assets/icon-source.png` (the file is untracked, so a bare `git mv` fails).
- `scripts/make_icons.rs`-style generator as a small standalone Rust program under `scripts/icons/` (uses the `png` crate already in the tree; Python here has no Pillow). It extracts the glyph (D1), checks edges for fringe, renders each of 16, 20, 24, 32, 40, 48, 64, 128, 256 separately from the 1024 master with an area-average downscale, and thickens the arcs at 16/20/24 only if they merge.
- Outputs in `assets/`: `cadence.ico` (9 entries, 256 as PNG), `icon-<n>.png`, `glyph.png` (white on transparent), `glyph.svg` only if the trace is clean.
- Rewire: `cadence.rc`, `taskbar.rs`, `app.slint`, `mini.slint`, sidebar header, SMTC app icon (comes from the app ID icon file), README header and "Icon by Icons8" footer. Delete `assets/icon.ico` and `assets/icon.png`; grep for leftovers.
- Evidence: a contact sheet of all 9 sizes on a light and a dark taskbar colour.

**2. Tokens (A1 to A3, B2).** Write the audit to `docs/v1.5-part1-audit.md`. Create `ui/tokens.slint`: primitive colours, semantic colours (`bg-base`, `bg-elevated`, `bg-hover`, `bg-pressed`, `border`, `text-primary`, `text-secondary`, `text-tertiary`, `accent`, `on-accent`, `danger`, `art-placeholder`), spacing 4/8/12/16/24/32, radii 4/8/12/full, six type sizes with weights, durations 120/200/320, `ease-out` and `ease-in-out`. Near-duplicates merge to the nearest step (for example radii 9/11/14 and the 15 white-alpha variants). Remove `theme.slint`.

**3. Base components (A4).** `ui/base.slint`: `Button` (primary, secondary, ghost), `IconButton`, `Card`, `SectionHeader`, `ListRow` shell, each with default / hover / pressed / focused / disabled and the same feedback timing. Existing `PrimaryButton`, `SecondaryButton`, `RoundIcon`, `Chip`, mini `Btn`, the lyrics and dialog buttons, `NavItem`, `LibRow`, queue rows, menu rows and settings rows are rebuilt on them. `TrackItem` only swaps its background for the shell; its behaviour is untouched.

**4. Migrate every screen (A5, B).** File by file, smallest first, `lyrics.slint` last. Snapshot-diff each against step 0. Page change becomes fade plus 8 px slide (today 16 px, 220 ms). Finish with a grep for hex, px and ms literals outside `tokens.slint`.

**5. Request layer (C3).** One shared `reqwest::Client` in a new `src/http.rs`, used by the Web API, art and lyrics. In-flight dedupe for identical GETs. 429: wait `Retry-After`, then retry. 5xx and network errors on idempotent calls: exponential backoff, capped (about 0.5 s doubling to 8 s, 4 tries). POST is never auto-retried. Page sizes set to each endpoint's documented maximum (I will check the current docs rather than assume). Token handling in `web.rs` is not touched.

**6. Cache-first launch (C1, C4).** `browse::init` runs right after the window is created, before auth. Home, Liked Songs, playlists and the sidebar render from SQLite and the API disk cache. `api::get` gains a stale-while-revalidate path: return the cached value now, refresh in the background, and apply only if the data changed. In-place updates keep the scroll position: models are patched (row changed / appended / removed), never reset. Cache temp files get unique names. A test asserts no cache file contains the access token, refresh token or Client ID.

**7. Lists (C2).** "Show all" grids and artist discography become `ListView` over rows of cards. Search results stay as they are in behaviour but move to a virtualized list. Playlist paging appends instead of rebuilding, and fetches ahead of the scroll position so the end is never reached with nothing loaded. Liked Songs refresh patches in place.

**8. Art pipeline (D, G).**
- `art::pick_image(images, display_px, scale_factor)` replaces `pick_url`; no 64 px source for anything above row size. Used at every call site, including the SMTC thumbnail (largest).
- SQLite library gains the image list per item (additive column, old rows fall back) so shelves stop upscaling 64 px art.
- Small scheduler inside `art.rs`: two classes (visible, prefetch), newest-first for visible, bounded queue so requests for rows scrolled past fall out and are re-requested if they return, bounded parallel downloads, cached art served without waiting for a download slot. Tasks for an abandoned page are aborted, not just ignored.
- LRU by bytes with an explicit budget (sized after measurement, target under 12 MB), keyed (url, px).
- Mini player, bar, lyrics page, side panel, queue, headers each request their own size. Cached small copy shows first, sharp one fades in. `Cover` gets the placeholder, the fade, `image-fit: cover` and smooth scaling.
- Benchmark `zune-jpeg` + `fast_image_resize` against the current decoder on real covers (64 / 300 / 640 px sources to 52 / 160 / 540 px). Adopt only if faster; report numbers either way. `zune-jpeg` is already in `Cargo.lock` through Slint; `fast_image_resize` would be new.

**9. Memory and idle (E, B5).** Audit every cache, map, channel and task for a bound (`TITLES`, `READABLE`, nav history, models, bodies). Stop the mini and podcast timers when not needed. Check for `Rc` cycles in the model closures.

**10. Renderer check (F).** Build once with `renderer-skia`, measure idle memory, CPU, scroll frame times and exe size against femtovg, keep one. If skia's prebuilt binaries are unavailable for this toolchain I report that and keep femtovg.

**11. Verify, commit, report.** Section 4 below. Update `CHECKLIST.md`. Commit on the branch; no push, no release, no version bump.

## 4. How each thing is verified

- **Visual regressions**: snapshot diff per page against step 0.
- **Scale 100 / 125 / 150 %**: `SLINT_SCALE_FACTOR` with a snapshot of the mini player, plus a check that the decoded cover is at least display px times scale. I cannot change your Windows display scaling; one manual look at 125 % from you closes it.
- **1000 liked songs / 1000 playlists**: a seeded SQLite library in an isolated profile, with a test-only scroll hook (behind the existing `smoke` feature, not in release builds).
- **Memory**: working set sampled at idle, after 3 full scrolls of 1000 liked songs, after 20 playlists, and over a scripted 30 minutes. Reported as a table.
- **Idle CPU**: 5 minutes idle, CPU time delta.
- **UI thread**: debug-build assertion that decode and HTTP never run on the UI thread.
- **Light and dark taskbar**: contact sheet from step 1. I will not flip your Windows theme; the real taskbar check is yours.
- **Signed-in flows** (cache-first launch with your real library, 20 real playlists): need D10.

## 5. Risks

1. **Token migration regressions**, especially `lyrics.slint` (43 hex, 136 px lines, hand-tuned). Mitigated by snapshot diffs and doing it last.
2. **Merging near-duplicates changes pixels slightly** (a 9 px radius becoming 8). Intended by the spec; I list every merge in the audit.
3. **Cache-first before auth** touches startup ordering. Auth and token code are not modified, only when `browse::init` is called.
4. **SQLite column add** must be additive and tolerate old rows.
5. **Scroll position on refresh** depends on patching models; a missed path would jump. Covered by the seeded scroll test.
6. **Skia** may not build here or may add several MB.
7. **Measurements while you are gaming** will be noisy for CPU and frame times; memory is unaffected.
8. **Scope**: this is large. If something has to give, the order of priority is correctness of C/D/E/G, then A/B completeness, then F.

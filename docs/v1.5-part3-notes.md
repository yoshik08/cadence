# Cadence v1.5, Part 3: notes

## Probe (2026-11-12)

The stored access token had expired, and refreshing it from outside the app could rotate the
refresh token under the user's running Cadence, so the probe read the 15 real search responses
Spotify returned to this app that sit in its API cache (`%LOCALAPPDATA%\cadence\cache\api`).

| Field | Present? |
|---|---|
| `track.popularity` | **no** (0 of 150 tracks) |
| `artist.popularity`, `artist.followers`, `artist.genres` | **no** (0 of 150 artists) |
| `album.popularity` | no |
| `album.album_type`, `album.release_date`, `album.total_tracks` | yes |
| `track.album.album_type`, `track.external_ids` (ISRC) | yes |
| Limit per type | **10** (every response; dev-mode cap) |

Design consequence: no popularity anywhere, so the popularity signal is Spotify's own result
position (earlier ranks higher), plus personal signals and version handling, as the spec says
for this case. The popularity code path exists and is unit-tested but stays dormant until Spotify
sends the field. The near-zero-popularity filter likewise needs the field and is inactive.

## Defaults chosen

- **Artist as Top result** needs the normalized name to equal the query *and* one of: followed,
  in Cadence's play history, or the primary artist of at least 2 of the top 5 ranked songs
  (with no popularity or followers, that is the only "clearly strongest" evidence available).
- **Album as Top result**: the layout already has an album tile, so albums compete, but only with
  an exact normalized title match and an artist the user follows or plays.
- **Artists section**: artist results that are artists of the top 5 ranked songs, plus artists
  whose normalized name equals or starts with the query and who are followed or in history.
  Artists of songs that the artist search did not return are not added (they would need extra
  requests for their pictures).
- **Song tile type line** reads "Song · Artist" with the app's existing "·" separator.
- **Debounce** 250 ms (was 280). The searched types and limit are unchanged.
- **Recently played**: a card's uri is `recent:<track uri>` so the card body can open the album
  while Play starts the exact track; the context menu treats it as the track.

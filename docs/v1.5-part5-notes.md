# v1.5 part 5: first-launch setup, updater, release prep, notes

## Storage design
- Client ID: `%APPDATA%\cadence\client_id.txt` (first line, trimmed, BOM stripped) is the only
  store. Startup reads the file first; if it is missing or invalid and `SPOTIFY_CLIENT_ID` holds
  a valid ID, that is written to the file (atomic temp + rename, then read back). Valid = 32 hex.
- Tokens stay where they were: `web_token.json` (Web API) and `librespot\credentials.json`
  (streaming). Neither holds the Client ID; streaming uses librespot's own client ID, so the
  user's Client ID only matters for the Web API.
- Debug builds only: `CADENCE_DATA_DIR` replaces `%APPDATA%\cadence` (tests never touch the real
  folder). Unit tests pass explicit temp folders to the storage and updater functions.

## Release asset
- v1.4 shipped one portable `cadence.exe` (GitHub asset with a `sha256:` digest). No installer,
  no zip, no workflow. The updater therefore swaps the exe: rename the running exe to
  `cadence.exe.old`, copy the new one in, start it, quit.

## Scopes (section E)
- `web::SCOPES` is unchanged between v1.4 and v1.5 (diff against master is empty), so updating
  from 1.4 asks for nothing. The existing check (`Token::has_scopes`) only re-asks when a scope
  is missing; the status line then explains why.

## Defaults chosen
- Change Client ID signs in with the new ID first (token written to a side file); only after
  that succeeds are client_id.txt and web_token.json replaced, then Cadence restarts. If the new
  sign-in fails nothing changes. (Stricter than "replace, then sign in": the old login always
  survives a failed change.)
- Sign out (new, Settings > Account): deletes only web_token.json and
  librespot\credentials.json, then quits; the next launch asks for both approvals again.
- Re-authorize keeps the old token until the new sign-in succeeds (it used to delete it first).
- Invalid client: a token/refresh answer `invalid_client` keeps every file, shows "Spotify
  doesn't recognize this Client ID" and a Change Client ID button. Spotify shows its own error
  page in the browser for an unknown ID on the consent screen; Cadence can't see that page, so
  the sign-in then times out after 5 minutes with the same message path.
- Setup card: shown only when no valid ID exists (checked at launch); streaming sign-in waits
  until the card finishes so two browser tabs never compete. Step labels "Step 1 of 2" (library)
  and "Step 2 of 2" (streaming; skipped when cached).
- Updater: check 8 s after launch on the runtime, 5 s timeout, User-Agent `Cadence-updater`.
  Asset = the one named `cadence.exe`. SHA256 from the asset `digest` field, else a
  `cadence.exe.sha256` asset when present; size always checked. Download to `update\`
  (`cadence.exe.download` -> `cadence.exe` after verification). Marker `update\applying`.
- `.old` copy: kept through the first launch of the new version (rollback), deleted on the
  launch after that.
- Debug builds only: `CADENCE_UPDATE_URL` replaces the GitHub API URL (fake endpoint tests).
- Settings badge: a dot on the sidebar Settings entry when an update is available.
